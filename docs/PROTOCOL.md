# 协议与实现

本页对应仓库中的 `HuaweiScaleClient`，不是官方协议保证。参考 openScale 提交 `8ef93b2092745ea84ddd677eac1871452c27b3d5`，目标华为体脂秤 3。

## 连接与认证

BLE Tracker 从广播中匹配配置的 MAC → ESPHome BLE Client 连接 → 按服务/特征 UUID 查找 → 串行注册通知并写 CCCD → 认证挑战 → RootKey/WorkKey 协商 → 读取原有 HUID → 原样透传 HUID 的协议资料同步 → 接收测量。

服务 `0x181C`：

| 角色 | 特征 UUID |
|---|---|
| 认证请求 | `02b2a08e-f8b0-4047-b1fd-f4e0efeee679` |
| 认证 token | `32330a04-15d9-421a-91c5-2a2d5c7525c9` |
| 工作密钥 | `a3d330f8-b84f-4f48-a78c-f8d1e33b597a` |
| 现有管理资料 | `4338c65e-ed8e-4085-bbea-a25e33ca6b54` |
| 用户资料 | `8cc61d7d-66c0-4802-89c3-38c5a163592e` |

实时测量位于服务 `0x181B`、特征 `46797c17-d639-488d-9476-4789e8472878`。可选状态查询/结果位于服务 `0x1805`；不订阅无关历史/绑定/设备信息特征。

WSP 写帧头为 `0xDB/0xDC`，通知为 `0xBD/0xCD`。15 字节分片，接收重组与 CRC16-XMODEM/Modbus 校验；认证使用 HMAC-SHA256、密钥派生与 AES-128-CTR，通过 ESP-IDF 的 mbedTLS 实现。没有将协议密钥写在代码里。

## 测量字段

只对已解密、通过长度检查的 26/38 字节测量负载解析：

| 偏移 | 内容 |
|---|---|
| 0..1 | 小端体重，除以 100 得 kg |
| 12..23 | 六个低频阻抗候选，小端 16 位；Scale 3 除以 10 得 Ω，选择首个有效候选 |
| 24..25 | 小端心率，1..240 bpm 作为有效值 |

阻抗算法是当前型号规则，不套用其他 Hagrid 型号“低值已经是 Ω”的启发式。

每轮使用随机 ID；完整测量文本实体格式如下，数值仅为**虚构示例**：

```json
{"id":"0123456789abcdef","weight":70.0,"impedance":500.0,"heart_rate":72}
```

缺失阻抗/心率为 JSON `null`。晚到有效数据沿用同一 ID，不通过拼接三个单独实体生成记录。HA 以 ID 合并；时间是 HA 首次接收时间，不能还原秤离线称量时间。

## 生命周期与限制

- 每轮结束仅允许一次最终补读；已完成轮次不因同一状态再次无条件启动读取。
- READY 状态仍有约 3 秒间隔的状态查询，不是纯被动广播接收器。不能据此保证秤永不亮屏。
- 单片队列、收发重组及握手均沿用现有超时/容量限制。没有另加 RTOS 任务或 MQTT 队列。
- HA 多人身份来自参考范围/认领，不来自秤端的 `user1`。协议 Profile 不自动切换为当前实际称重的人，因此不以秤屏幕体脂率作为两人的最终身体成分结果。
- 原始质量数据留在本地；身体成分估算是在 HA 端用该条记录归属人的资料和实测阻抗重新计算。
